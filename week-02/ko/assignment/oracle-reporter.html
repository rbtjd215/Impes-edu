Oracle·Reporter 과제

증거·상태·기록의 경계를 참고해 Oracle의 판정과 Reporter가 남길 기록을 한 페이지로 제안합니다.

YOUR ASSIGNED ROLE

Oracle·Reporter

30–45 MIN

RH-CASE-01의 가상 실행 결과를 받았을 때 Oracle이 어떤 증거로 상태를 판정하고 Reporter가 무엇을 기록해야 하는지 제안합니다.

지정 읽기

  1. 스터디 노트 · 먼저 구분할 세 가지, State와 Trace, tests와 runs
  2. PentestGPT Agent README의 Memory and traces·Failure and restart behavior
  3. CAI architecture의 Tracing 목적과 구현 주의
01 · 내 책임

Oracle 또는 Reporter를 고릅니다

  • Oracle 판정 규칙·테스트 / Reporter 로그·결과표 중 하나
  • 내가 맡을 일을 한 문장으로 설명
02 · 입력과 출력

판정과 기록에 필요한 것을 적습니다

  • 전문 모듈에서 받을 정보 3개
  • 판정에 사용할 수 있는 증거
  • 반드시 남길 기록
  • 정보가 빠졌을 때의 상태와 질문
03 · 상태 규칙

네 상태를 구분합니다

  • PASS: 외부에서 확인 가능한 성공 증거
  • FAIL: 실행했고 실패 근거가 있음
  • UNKNOWN: 실행했지만 판정 근거 부족
  • NOT_RUN: 실제로 실행하지 않음
04 · 참고 구조

판정·기록 구조 하나를 고릅니다

  • RedHarness에 적용하고 싶은 점
  • 민감한 출력·개인정보·비밀값을 제외하는 방법
  • 추가로 확인할 점
05 · 3주차 MOCK

증거가 상태를 뒷받침하는지 확인합니다

  • 가상 결과 한 건과 기대 판정 상태
  • 그 상태에 필요한 증거
  • 일부 정보가 빠진 실패 예시 한 건
  • 아직 모르는 점 또는 팀장에게 물을 질문

완료 확인

  • PASS, FAIL, UNKNOWN, NOT_RUN을 구분했는가?
  • AI의 주장과 확인 가능한 증거를 구분했는가?
  • 민감한 정보나 비밀값을 기록하지 않는 기준을 적었는가?
