CONNECTING LAST WEEK W02-S02

What stages make up one harness task?

A harness is not a filename or an AI role. It is an execution structure that connects an AI proposal to program-controlled tool calls, result checks, and records. Following the sequence separates what the AI said from what actually happened.

Goal inputWhat should happen?
→
Choose actionAI proposal
→
Run toolprogram action
→
Observeactual return value
→
Judge & recordpreserve evidence

Example: if the AI says “look it up” but there is no tool return value, nothing has been observed yet.

CAI · FULL RUN W02-S04

CAI processes a request, then feeds the result back

First, the decision-making AI proposes a next action. The control program handles the response by calling a tool or handing the task to another AI. The tool result or new role's answer informs the next decision. CAI calls these Agent, Runner, Tool, and Handoff.

① Propose actionAgent · AI decides
→
② Process responseRunner · program controls flow
→
③ Run tool / hand offTool call or Handoff
→
④ Return resulttool value or new role's answer
Repeat or stopAt ③, the response determines whether a tool runs or ownership changes. The result drives another decision or ends the run.

CAI FULL RUN · ① PROPOSE ACTION W02-S05

The Agent turns goals and observations into a next request

An Agent is an AI role that reads the goal and observations so far, then answers or requests tool use. It is different from a human team assignment. For RH-CASE-01, it may propose “What should we inspect next?” The request itself is not a tool execution.

Goal & observationscurrent facts from the authorized exercise

CAI FULL RUN · ② PROCESS RESPONSE W02-S06

The Runner processes the next step from the response

The Runner is not an AI Agent. It is program code that manages execution order. It reads whether the Agent response means stop, call a tool, or hand off; then it adds a tool result to the next input or changes the active Agent.

AI responseanswer · tool request · handoff
→
Control programRunner · reads response type
→
Stop · tool · handoffprocess one matching step
RepeatWhen a tool result or new Agent answer arrives, the next decision begins.

CAI FULL RUN · ③ RUN TOOL W02-S07

A Tool actually performs the requested function

A Tool is not another AI role. It is a function that the program runs in response to an Agent request. Our classroom example uses a status check in an authorized practice environment. The return value is the observation; it is separate from a sentence in which the AI claims it “finished.”

→
Runner calls Toolprogram runs an authorized function
→
Return valueobservation such as “status: needs review”

CAI FULL RUN · ③ HAND OFF W02-S08

A Handoff transfers the task to another Agent

A Handoff is not a record file. It is an action in which the current Agent transfers work to another Agent. When a handoff appears, CAI's Runner changes the active Agent and the input being passed, then continues the run.

CAI FULL RUN · RECORDING STEPS W02-S09

A Trace lets us reconstruct events in order

A Trace is the recording concept used to reconstruct decision requests, tool calls, and observations in time order. It does not imply one specific file named “Trace.” A final one-line answer is not enough to inspect the process and evidence.

PENTESTGPT FULL RUN · ①·⑤ STATE AND RECORDS W02-S16

Saved State continues the run; Trace reconstructs it

State is saved data to continue from. A Trace is a run record of events that already happened. In PentestGPT, state stored in a SQLite database is authoritative, while run events are recorded separately. The terms do not by themselves name specific files.

DATA THE NEXT RUN READS · STATE

Current context to continue

Includes items such as the current task, confirmed observations, and remaining limits.

DATA USED TO REVIEW · TRACE

Run events to reconstruct

Shows the order of selections, tool calls, returns, and errors. PentestGPT stores events in files.

SHORT DESIGN CAUTION W02-S21

Adding Agents also adds handoff and call costs

A token is not a feature or an Agent. It is a measurement unit for text sent to and received from a model. Adding an Agent may add calls and context to transfer. Compare success evidence, tokens, tool calls, and time using the same input.

ONE ROLE

Handle it in one flow

Decision and result stay within one flow.

TWO ROLES

Add a handoff

Specialization may help, but transfer costs must be checked.

Fewer roles or tokens do not automatically make a design better. We are not fixing the number today.

TWO SIMILAR-LOOKING INSTRUCTION FILES W02-S26

AGENTS.md and runtime prompts have different readers

AGENTS.md and prompt.md are both example document files, but their readers differ. AGENTS.md can hold working rules for a coding AI helping develop the repository. A module's prompt.md can hold goals and I/O instructions for the model used while RedHarness runs.

READ DURING DEVELOPMENT

AGENTS.md → coding AI

“Only edit your module. Read the shared contract first, then record verification results.”

READ WHILE THE HARNESS RUNS

prompt.md → module model

“Use the observation to propose a next action, then answer in the required format.”

Both instructions are classroom examples. The name AGENTS.md is optional, and a module without a model may not need a runtime prompt.
