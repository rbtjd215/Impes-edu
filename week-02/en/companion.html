Scope for Week 2

In Week 2, we only read official structure documents and a fictional classroom case. We do not run or install Claude, APIs, code, or security tools.

RH-CASE-01 is the fictional case ID for an authorized local login exercise. The inputs and observations below are not results from CAI or PentestGPT running this case.

Goal input → action proposal → permission check → tool execution → actual observation → verdict and record

Following this sequence helps us separate what the AI said from what the program actually did.

Three layers to separate first

LayerMeaningEvidence to inspect
AI proposalA response or tool request that suggests what to do nextModel response
Program controlCode that reads the request type and performs checks, tool calls, or handoffsCode path and run events
Actual observationA value returned by a tool or environmentOriginal return value and record

If the AI says, “I checked the status,” but there is no tool return, we have not confirmed an actual observation. Keep these three layers separate in design documents.

RunnerControl programReads whether the Agent response means stop, call a tool, or hand off, then processes that step.
ToolActual functionPerforms an approved function when the Runner calls it and returns a value.

An Agent request is not an execution result

An Agent may propose, “Check the practice environment status.” The real action occurs when the Runner calls a Tool. The value returned by the Tool is the observation, and that value becomes input for the next Agent decision.

A Handoff is an action, not a file

When a Handoff occurs, the Runner changes the active Agent and the input passed to it. A handoff may include the goal, needed observations, and next question. The three items in the classroom diagram are not a fixed CAI file format.

A caution about Trace in CAI

The CAI architecture presents tracing as a design pillar, but the archived material reviewed for class marks its implementation as work in progress. Do not read the classroom timeline as an actual CAI log format.

One run through PentestGPT

Read saved State
  → Supervisor proposes one next task
  → Deterministic code checks the task and allowed scope
  → Executor handles the approved task
  → Actual observation updates State and Trace
  → Next task or stop
TermPlain meaningRole in one run
SupervisorTask-selection AIReads the saved situation and proposes one next task.
Deterministic checkProgram that applies defined rulesChecks target scope, task validity, evidence sources, and conditions for state changes.
ExecutorTask-handling AIReceives one approved task, handles it, and records the actual observation.
StateSaved data for continuing a runStores items such as the current task, confirmed observations, and remaining limits.
TraceRecord of past run eventsReconstructs the order of selections, calls, returns, and errors.

Code can check explicit rules

Defined conditions such as an allowed target, a request limit, or a required input can be checked by deterministic code instead of another AI role. The isolated execution environment should also restrict actual tool permissions.

State and Trace serve different purposes

State tells the next run where to continue. Trace shows what happened and in what order during an earlier run.

After an interruption, the system needs State such as the last task, actual observation, and remaining limits. To investigate a failure, it needs a Trace of task selection, tool calls, return values, and errors.

The goal is not to copy either structure. We read where each project places responsibility, then use that comparison to ask what RedHarness needs.

Connecting the examples to RedHarness

RH-CASE-01 input
  → Dispatcher
  → Select Specialist Module A or B
  → Oracle
  → Reporter
  • Dispatcher: Reads the case input and selects the appropriate Specialist Module A or B.
  • Specialist Module A/B: Interprets observations, proposes a next action, and uses approved tools to obtain an actual observation.
  • Oracle: Compares a claim with the original observation and decides whether the evidence is sufficient.
  • Reporter: Records status, evidence, errors, and the next action in a reproducible form.

The starting design selects either Specialist A or Specialist B according to the input. We will consider parallel execution only after defining shared inputs, outputs, and merge rules. The four responsibilities do not automatically require four separate AI Agents.

The loop inside a specialist module

Shared input
  → AI proposes a candidate next action
  → Deterministic code checks scope and limits
  → Approved Tool runs
  → Actual observation is saved
  → Repeat if evidence is insufficient, otherwise send to Oracle

Observation interpretation and action proposals are candidates for AI work. Deterministic code can manage scope checks, limits, and tool calls. We will test the exact loop limit and stop condition with a shared contract and mocks starting in Week 3.

Role count and cost

Adding an Agent may separate specialized responsibilities, but it can also add model calls and handoff context. Compare designs with the same input and inspect evidence, tokens, tool calls, execution time, and failure records. In Week 2, we assign human project responsibilities. We do not set the final number of AI Agents.

A Contract is the agreement about inputs and outputs between modules, not a required filename. PROJECT_SPEC.md is one possible document for recording that agreement.

AGENTS.md and prompt.md

Example fileReaderPurpose
AGENTS.mdCoding AI that helps develop the projectExplains edit scope, shared references, verification, and recordkeeping.
Module prompt.mdModel used while RedHarness runsExplains the module goal, input, output, and action criteria.

The files have different readers and are used at different times. A module that does not use AI may not need a runtime prompt. The team may also choose different filenames.

tests and runs

  • A Mock is a testing method that substitutes a predefined return value for a real tool.
  • tests/ is an example location for repeatedly checking the contract and behavior with fixed inputs and mocks.
  • runs/ is an example location for run events, observations, and errors. The team must remove secrets and decide which records belong in Git.

Asking a coding AI to do project work

The request “Build a harness” does not identify the reference or scope. Include these four parts.

PartQuestionClassroom example
ReferenceWhich documents and examples should the AI follow?Shared contract and assigned module specification
TaskWhat should the AI create or change?Draft mock input and output for RH-CASE-01
ScopeWhich files and actions are allowed?Assigned module only, with no network or API execution
VerificationHow will a person decide that the work is complete?Expected result and explanation of changed files

A clear request limits unintended scope expansion and gives a person a concrete review standard.
