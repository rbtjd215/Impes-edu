02 · GitHub·Git·개발 저장소 준비

할 일

  1. 본인 GitHub 계정으로 로그인하고 개발 저장소의 초대를 수락합니다. 초대를 받지 못했으면 담당자에게 요청하세요. 공개 저장소는 초대 없이 읽거나 clone할 수 있지만, 본인 브랜치를 업로드하려면 권한이 필요합니다. 초대·인증이 미완료여도 로컬 준비와 자료의 읽기 검토를 할 수 있으며, 업로드 완료로 표시하지 않습니다. GitHub 초대 안내
  2. 앱이 아직 없다면 먼저 설치합니다. 공식 시작 안내의 데스크톱 설치에서 Windows 또는 macOS에 맞는 앱을 받고, 본인 ChatGPT 계정으로 로그인한 뒤 Codex 작업 화면을 선택합니다. Windows는 공식 Windows 설치 안내도 참고하세요. 이미 Codex를 사용할 수 있다면 설치를 반복하지 않습니다. Git은 변경 이력을 관리하는 로컬 도구이고, GitHub는 이를 함께 보관하고 PR을 만드는 서비스입니다.
  3. 컴퓨터에 Git과 Python이 있는지 확인합니다. 없다면 Codex에게 운영체제를 알려 주고 설치를 요청할 수 있습니다. 설치·인증에 사람의 조작이나 권한 승인이 필요하면 안내에 따라 진행합니다. Git 다운로드, Python 다운로드
  4. 저장소를 처음 가져오는 작업을 clone이라고 합니다. 이미 가져온 폴더가 있다면 다시 복제하지 않고 그 폴더를 사용합니다.
  5. 커밋에 남길 공개 표시 이름과 이메일을 확인합니다. GitHub Settings → Emails에서 본인의 noreply 주소를 확인해 사용할 수 있습니다. 다른 사람의 이름·이메일을 대신 넣지 마세요. GitHub 커밋 이메일 안내

처음 준비하는 분: 폴더를 두 번 선택합니다

① 설치 도움을 받을 빈 준비 폴더를 만드세요. 예를 들어 컴퓨터에 RedHarness_준비 폴더를 만들고, Codex에서 프로젝트 추가로 이 폴더를 여세요. 폴더 여는 방법은 03절을 참고하세요.

② 아래 준비 요청문을 보내세요. Codex가 Git·Python 준비를 돕고, 준비 폴더 안에 개발 저장소를 내려받습니다. 내려받은 폴더 이름은 Impes_RedHarness입니다.

③ 복제가 끝나면 작업 폴더를 바꾸세요. Codex가 알려 준 경로에서 새로 생긴 Impes_RedHarness 폴더 자체를 선택해 프로젝트에 연결합니다. 준비 폴더는 설치 도움을 받는 출발점이고, 실제 개발은 저장소 폴더에서 진행합니다.

④ 저장소 프로젝트에서 새 채팅을 여세요. 03절의 경로 확인을 마친 뒤 04절로 넘어갑니다. Codex가 복제 완료를 알리면 다음에 선택할 정확한 저장소 경로를 확인하세요. 준비 폴더의 채팅에서 곧바로 개발을 시작하지 않습니다.

예를 들어 폴더가 다음처럼 생겼다면, 마지막에 선택할 곳은 아래의 Impes_RedHarness 폴더입니다.

RedHarness_준비/
└─ Impes_RedHarness/  ← 복제 후 Codex에 연결할 실제 작업 폴더
   ├─ AGENTS.md
   ├─ README.md
   └─ 03_프로젝트/

이미 복제한 저장소가 있다면 그 Impes_RedHarness 폴더를 바로 연결하고 03절에서 경로를 확인합니다.

03 · Codex에 로컬 프로젝트 연결

할 일

  1. Codex 화면의 Add new project 또는 프로젝트 추가 메뉴를 엽니다. Windows에서는 Ctrl+O로 폴더 선택을 열 수 있습니다. 버전에 따라 메뉴의 번역·위치는 달라질 수 있습니다. Windows 공식 안내
  2. 복제한 Impes_RedHarness 폴더 자체를 선택합니다. 상위 Projects 폴더나 03_프로젝트 하위 폴더를 선택하지 않습니다.
  3. 이미 프로젝트가 있으면 재사용합니다. 준비용 폴더를 열었다면 프로젝트 메뉴의 Edit project에서 복제본을 연결하고 기본 작업 폴더(Make primary)로 지정하거나, 복제본으로 새 프로젝트를 만듭니다. 새 채팅의 기본 Git 작업과 규칙 탐색은 기본 폴더를 사용합니다. 프로젝트 공식 안내
  4. 해당 프로젝트 안에서 새 Codex 채팅을 만들고 Local / This computer로 진행합니다. 이 안내는 자기 컴퓨터의 복제본을 기준으로 합니다. 실행 환경 공식 안내

막혔을 때

AGENTS.md나 Git 저장소를 찾지 못하면 프로젝트의 기본 폴더를 확인합니다. 잘못 선택했다면 복제본 루트로 다시 연결하고 새 채팅에서 경로를 재확인하세요. 같은 로컬 복제본에서 여러 채팅을 동시에 수정하면 변경이 섞일 수 있습니다. 본인의 미완료 작업을 이어갈 때는 그 브랜치와 폴더의 변경을 그대로 이어받습니다. 관련 없는 작업을 새로 시작하거나 같은 컴퓨터에서 동시 수정이 필요할 때만 Codex와 별도 worktree 사용을 정하세요. worktree를 만들면 실제 작업 경로와 브랜치를 다시 확인합니다.
